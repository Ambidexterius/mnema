# Подключение писем Мнемоники

Статус на 11.11.2026: код очереди, шаблон HTML/plain text и SMTP-транспорт подготовлены; настоящий SMTP ещё не подключён. Реальные письма не отправлялись.

Рекомендуемый вариант — Yandex Cloud Postbox. Первые 2 000 исходящих писем в месяц не тарифицируются; далее действует тариф сервиса. Проверено 11.11.2026: https://yandex.cloud/ru/docs/postbox/pricing.

1. Нужен домен, DNS которого вы можете менять, и адрес отправителя, например `notify@example.org`. Домен Amvera принадлежит хостингу: подтвердить его как собственный отправитель нельзя без управления DNS.
2. В Yandex Cloud создать/выбрать каталог, активный платёжный аккаунт и сервисный аккаунт с ролью `postbox.sender`. Создать адрес в Postbox и подтвердить домен CNAME-записями DKIM по инструкции провайдера. SPF и DMARC настроить по его рекомендации, не создавая второй SPF TXT вместо обновления существующего. Инструкция: https://yandex.cloud/ru/docs/postbox/quickstart.
3. Создать SMTP API-ключ сервисного аккаунта. Данные внести **в переменные Amvera**, не в чат и не в файлы репозитория:

| Переменная | Значение |
|---|---|
| SMTP_HOST | postbox.cloud.yandex.net |
| SMTP_PORT | 465 |
| SMTP_SECURE | true |
| SMTP_USER | идентификатор SMTP API-ключа |
| SMTP_PASSWORD | секретная часть ключа |
| SMTP_FROM | Мнемоника <notify@example.org> — заменить домен |
| APP_URL | https://your-app.example.org |

Для другого SMTP подходят те же переменные. На порту 587 указать `SMTP_SECURE=false`: транспорт обязательно делает STARTTLS с проверкой сертификата. Параметры Postbox: https://yandex.cloud/ru/docs/postbox/operations/send-email.

После внесения параметров нужен перезапуск приложения, затем один настоящий тест: загрузить разрешённую короткую запись, дождаться обработки, подтвердить письмо в ящике, верность проекта/источников, доставку в основной ящик и отсутствие повторного письма при обычном опросе сервера. Оплаченные ресурсы и DNS автоматически не создавались.

## Поведение

- Звук из прикреплённого MP3 (1,23 с) — при переходе записи из обработки в готовое состояние в открытом проекте. По умолчанию включён; отключается в меню профиля. Browser AudioContext требует взаимодействия со страницей. При закрытой странице или блокировке звука воспроизведения нет. Основа: https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay.
- Письмо — загрузившему видео/аудио, по адресу аккаунта. Если запрошена автоматическая сводка, письмо ждёт её завершения; при ошибке сводки сообщает о готовой расшифровке. Если сводка не запрошена — письмо со ссылкой на готовый текст.
- Перед отправкой заново проверяются действующая учётная запись и членство в проекте. Отозванный доступ или удалённый материал отменяют отправку. Читатель не получает черновик сводки.
- HTML экранируется. Источники содержат адрес проекта и фрагмента; после входа открываются нужный проект и выделенный фрагмент.
- Очередь SQLite `mnema_completion_mail` переживает перезапуск, ключ — ID задания ASR. До 5 попыток при сбое SMTP. Ошибка почты не меняет готовность расшифровки. Message-ID стабилен; SMTP не гарантирует exactly-once при потере связи после приёма письма.
- Без SMTP-настроек новые письма не ставятся в очередь. Старые материалы массово не рассылаются после подключения. Ссылки приглашений по-прежнему передаются вручную.

## Проверки

33 теста: переходы состояний для звука, экранирование письма и ссылки, запрет черновика читателю, ожидание сводки, дедупликация задания, отзыв доступа, повтор после сбоя SMTP; интеграция загрузка → ASR-фикстура → письмо загрузившему. Настоящий SMTP пока не проверен.


## Public source distribution

The production notification MP3 is supplied privately and is not included in this public repository. Before building your own deployment, place a sound file you may use at app/public/sounds/transcription-complete.mp3. Without that file the visual completion message still works; playback remains silent.
